딜리칩 데이터 추출 작업을 수행해줘.

== 목표 ==
COUP 폴더 이미지를 분석하여 COUP.json을 최신 데이터로 덮어써.
기존 웹사이트 카드 UI 코드는 절대 수정하지 않는다.

== 공통 원칙 ==
1. 화면에 명시적으로 표시된 텍스트·숫자만 추출. 임의 계산·추론 금지.
2. 쿠폰·프로모션 카드만 추출. 매장 리스트·리뷰·광고·추천 섹션은 완전히 무시.
3. "받기 완료" "종료" "마감" 상태 쿠폰은 제외.
4. 동일 브랜드 이미지가 여러 장이면 하나의 레코드로 합쳐서 처리.
5. 한 이미지에 여러 카드가 있으면 상단→하단 순서로 전부 추출.

== 공통 필드 규칙 ==
- app: "쿠팡이츠"
- brand: 순수 브랜드명만. "할인" "최대" "이번주" "쿠폰" 등 수식어 제거.
- discount: 숫자만.
  % 할인 쿠폰은 최대 할인 금액을 숫자로 기록.
  최대 금액 명시 없이 %만 있으면 해당 레코드 제외.
- min_order: 숫자만. 명시 없으면 null.
- method: "배달" | "픽업" | "전체". 불명확하면 "전체".
- delivery_types: 명시된 태그 배열. 없으면 [].
- special_condition: 부가 조건 텍스트. 없으면 null.
- valid_until: YYYY-MM-DD 형식. (없으면 null)

== JSON 출력 형식(필수) ==
[
  {
    "app": "쿠팡이츠",
    "brand": "브랜드명",
    "discount": 4000,
    "min_order": 15000,
    "method": "전체",
    "delivery_types": [],
    "special_condition": null,
    "valid_until": "2026-04-20"
  }
]

== 쿠팡이츠(COUP) 추출 규칙 ==

■ 목록/브랜드컬렉션 페이지 이미지:
  - "최대 XX원"으로 표시된 브랜드 → 해당 이미지에서 추출하지 말 것.
    (같은 폴더에 해당 브랜드의 상세 페이지 캡처가 별도로 있음)
  - 고정 금액(예: "5,000원")으로 표시된 브랜드 → 해당 금액 그대로 추출.

■ 가게 상세 쿠폰 페이지(혜택 모아보기) 이미지:
  - 이 이미지가 있으면 해당 브랜드는 이 페이지 기준으로만 추출.
  - "중복 가능한 할인" 섹션의 쿠폰 카드를 각각 별도 레코드로 추출.
  - 쿠폰 카드에 "배달" 태그 → method: "배달"
  - 쿠폰 카드에 "포장" 태그 → method: "픽업"
  - "X원 이상 주문 시" → min_order에 해당 금액 기록.
  - "와우회원 배달비 0원" 혜택 → delivery_types에 "배달비 0원" 추가 (별도 레코드 X).
  - "즉시할인" → 별도 레코드로 추출 (special_condition: "즉시할인").

■ 기간 표시 변환:
  - "X월 N째주까지" → 해당 월의 N번째 일요일로 변환.
    예) "4월 셋째주까지" → 2026-04-20, "4월 넷째주까지" → 2026-04-27
  - "YYYY/MM/DD까지" → YYYY-MM-DD 형식 변환.
  - 없으면 null.

■ 기타:
  - 랜덤박스: 열어서 나온 최솟값 기준.
  - 선착순:
    - special_condition에 "선착순 HH:MM부터" 형식으로 기입.
    - 이미지에 시간이 명시된 경우 해당 시간으로, 미표시 시 "선착순"만 기입.
  - delivery_types: 명시된 문구 그대로. 없으면 [].

== 새 브랜드 처리(필수) ==
추출된 브랜드 중 scripts/sync-all-data.js의 categoryMap에 없는 브랜드가 있으면:
1. 해당 브랜드 업종을 파악하여 아래 카테고리 중 하나로 분류.
   chicken / pizza / burger / korean / bunsik / meat / chinese / japanese / western / cafe / bakery
2. sync-all-data.js의 categoryMap 해당 섹션에 직접 추가.

== 품질 검증(필수) ==
- app / brand / discount 중 하나라도 비어있는 레코드는 배열에서 제외.
- 카드 수가 0이거나 비정상적으로 적으면 해당 이미지 재분석.
